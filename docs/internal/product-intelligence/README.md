# NimCarry — Continuous Product Intelligence

This directory keeps NimCarry moving beyond a hackathon submission and toward a durable product.

## Product thesis

NimCarry is a **verifiable human handoff layer** for situations where responsibility must move from one real person to another before reaching the intended destination.

The product should earn repeat use because it solves a real coordination problem, not because it adds more crypto UI.

## Operating loop

```
Observe → Mine hidden problems → Form hypothesis → Design smallest experiment
→ Measure behavior → Promote / Iterate / Kill → Update product thesis
```

Inputs:
- real product analytics and user feedback;
- repo/runtime evidence;
- community complaints and adjacent-product research;
- LLM Product Council critiques;
- security/abuse findings;
- visual and interaction reviews.

Outputs:
- stronger user jobs;
- tested retention loops;
- differentiated Nimiq-native mechanisms;
- safer product behavior;
- monetization experiments;
- visual improvements tied to the product concept.

Prompts live in [LLM-COUNCIL/prompts](LLM-COUNCIL/prompts).

## Decision rule

LLM output is **hypothesis material**, never product truth.

Every promoted change should have:
1. a concrete user problem;
2. supporting evidence or a deliberately stated assumption;
3. a smallest meaningful experiment;
4. a success/failure metric;
5. an explicit safety/privacy boundary;
6. a decision: **PROMOTE / ITERATE / KILL / HOLD**.

## Current north-star ladder

**Registered → Nimiq Verified → Activated → Finalized → Repeat Usage → Paid Usage**

Registration is acquisition, not proof of meaningful use.

## Public vs private

This directory contains reusable product intelligence, hypotheses, and experiment design. Raw private user data, emails, LLM transcripts with sensitive content, operational secrets, and internal handoffs do not belong here.
