# Visual & Interaction Opportunities

Goal: make NimCarry recognizable as a **human custody / handoff product**, not a generic Web3 mini app.

## Core visual metaphor

The interface should make responsibility feel like it is physically and verifiably moving.

Strong primitives:
- custody passport;
- handoff stamps;
- route thread;
- current-holder seal;
- acceptance mark;
- FINAL proof stamp;
- destination arrival receipt;
- broken-route / reroute state.

## Screens to reconsider

### Profile
Current role: registration + wallet connection.

Opportunity:
- frame wallet verification as “prove your handoff identity”;
- make verified state feel earned and trustworthy;
- reduce technical vocabulary.

### Mission home
Opportunity:
- make “who has responsibility now?” the strongest visual element;
- show next action and route health;
- avoid dashboard-card overload.

### Invitation
Opportunity:
- make consent legible as a human decision;
- show what the bridge is accepting;
- include expiry/fallback.

### Pass
Opportunity:
- make 1 NIM visibly the custody baton;
- clearly separate approval, broadcast, FINAL.

### Route receipt
Opportunity:
- turn completion into a memorable shareable artifact;
- maintain privacy-safe redaction;
- show evidence classes rather than raw technical details.

## Motion grammar candidates

- Accept → stamp settles into route.
- Pass initiated → baton moves only to a pending threshold, never to the next holder prematurely.
- FINAL → holder marker snaps to next person.
- Reroute → broken route segment retracts; new accepted branch grows.
- ARRIVED → passport closes / receipt seals.

Reduced-motion equivalents are mandatory.

## Anti-AI-slop checks

Avoid:
- generic neon crypto gradients;
- random glass cards;
- decorative blockchain nodes;
- black/blue “agent dashboard” defaults;
- motion with no custody meaning;
- generic SaaS KPI surfaces where route state should dominate.

Prefer:
- domain-native materials;
- restrained evidence marks;
- human names/roles before wallet strings;
- visual continuity from invite → acceptance → pass → receipt.
