# Shared Evidence Pack for Every LLM

Use this before the role-specific prompt.

## Product

NimCarry: https://github.com/Faadil1/nimcarry  
Live: https://nimcarry.faadil-casecraft.workers.dev  
Usage evidence: https://nimcarry.faadil-casecraft.workers.dev/real-usage

Current concept:
- destination-bound human routing;
- one willing person hands responsibility to another;
- exactly 1 NIM acts as a custody baton;
- only independently verified FINAL changes custody;
- human profile registration can happen before wallet connection;
- Nimiq wallet control is verified by signature;
- current real-usage policy separates Registered → Nimiq Verified → Activated → Finalized.

Current evidence boundary:
- registration is acquisition, not activation;
- approval ≠ broadcast ≠ FINAL;
- historical test activity cannot be promoted into current traction after wallet linking;
- no PII should be published as usage evidence.

Current product ambition:
- become useful outside the hackathon;
- solve a recurring real-world handoff problem;
- create repeat usage;
- be visually memorable and domain-native;
- find a sustainable business model;
- preserve privacy/safety;
- use Nimiq because verifiable custody needs it, not because the competition requires it.

Useful external lesson:
https://blog.surfstyk.com/i-asked-the-internet-to-hack-my-nimiq-mini-app/
Key principle to challenge: cheap-to-manufacture metrics should not carry the strongest real-usage claim.

## Non-negotiable method

Do NOT give a generic feature wishlist.

First:
1. inspect the repo/live product where possible;
2. identify hidden user jobs and contradictions;
3. separate EVIDENCE from HYPOTHESIS;
4. generate divergent concepts before feasibility filtering;
5. then apply safety, regulatory, cost, and implementation constraints.

Prefer meaningful action loops over passive dashboards.

Do not assume read-only features are safer/better by default.

Do not copy competitors or prior hackathon winners literally. Extract mechanisms.
